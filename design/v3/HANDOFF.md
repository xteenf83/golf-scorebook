### 시안 파일 읽는 법
`.dc.html`은 디자인 캔버스용 형식이다. **그대로 복사해 쓰지 말고 명세서로 읽는다.**
- 화면 구조와 모든 수치(색·크기·여백·모서리)는 인라인 `style`에 있다.
- `{{t.xxx}}` 는 테마 토큰(Home.dc.html 하단 `renderVals()`의 `t` 객체 = 라이트/다크 값).
- `<sc-for>` = 반복, `<sc-if>` = 조건 표시. 차트 좌표 계산은 `renderVals()` 안의 JS를 참고.
- 숫자는 전부 **체험용 예시**다. 실제 앱에선 저장된 라운드 데이터로 계산한다.
- `/_blob/...` 이미지 경로는 `images/` 폴더의 파일로 바꾼다.

## 1. 절대 지킬 것 (기존 원칙 유지)

1. **라운드 중 입력 속도**: 평범한 홀은 "다음 홀" 한 번으로 끝(기본값 파·2퍼트·페어웨이·직진 유지).
2. 버튼·터치 영역 **44px 이상**, 햇빛 아래에서 읽히는 대비(본문 4.5:1 이상).
3. 아이폰 폭 **375–430px**에서 깨지지 않기. 라이트/다크 모두(아이폰 설정 따름).
4. **단일 HTML, 빌드 도구 없음**. 외부 라이브러리는 Firebase, 글꼴만 추가 허용.
5. **오프라인 동작 유지**: 새 이미지·글꼴도 서비스워커 캐시에 넣는다.
6. **데이터 구조(Firebase/로컬 저장 형식) 변경 금지**. 새 분석은 전부 기존 데이터로 계산.
7. 입력 방식 3가지(홀별/홀별 타수만/총타만) 모두 자연스럽게 보이게. 정보 없는 항목은 숨김("—" 또는 섹션 생략).
8. 9홀 라운드는 통계 제외(목록·고스트·브리핑에는 사용) — 기존 규칙 유지.
9. **좌타 기준 방향**: 구질 버튼·차트는 공이 간 방향 순서 좌→우 = 슬라이스·페이드·푸시·직진·풀·드로우·훅.
10. 애니메이션은 아이폰 사파리에서 끊기지 않게(transform/opacity만, filter·움직이는 SVG 금지), `prefers-reduced-motion` 존중.

## 3. 공통 컴포넌트 (먼저 만들고 모든 화면에서 재사용)

1. **떠 있는 탭 바**: 좌우 12px, 아래 22px(+safe-area). 캡슐(4칸: 홈·분석·코스·배지) + 오른쪽 68px 초록 원 버튼.
   - 원 버튼: 진행 중 라운드 있으면 ▶(이어서 기록), 없으면 ＋(새 라운드). 기존 가운데 버튼 기능 그대로.
   - 활성 탭: 채운 아이콘 + --t1 굵게, 비활성: 선 아이콘 + --t2.
   - 기존 '더보기' 탭은 홈 오른쪽 위 ≡ 메뉴로 이동(내용은 동일).
   - 홀 입력 화면에선 숨김(기존처럼 이전/다음 홀 고정 버튼).
2. **세그먼트 컨트롤**: 회색 트랙 + 흰 손잡이(그림자 0 1px 3px rgba(0,0,0,.12)).
3. **기간 버튼 줄**: 5칸, 라벨 위 / 변화량 아래(색), 선택칸만 --fill 바탕.
4. **밑줄 탭**: 선택 = 굵은 검정 + 아래 3px 막대. 라운드 기록 상단 탭.
5. **목록 행(토스 종목 행)**: 50px 색 타일 + 제목/부제 + 오른쪽 값 2줄 + 끝 아이콘. 카드 상자 없이 회색 바탕 위.
   - 골프장 타일: 골프장 이름 앞 2–3글자(예 "서원", "레이크"), 색은 이름 해시로 [#0E9A5A,#3182F6,#6E5BFF,#F2683C,#00A7B5] 중 고정 배정.
6. **보라 알림 띠**: 아이콘 + 한 문장 + ›. (미션 안내, 고스트 결과)
7. **큰 알약 버튼 2개**(판매/구매 스타일): 왼쪽 연한 초록(--brand-soft/--brand-text), 오른쪽 초록 채움.
8. **스코어 표기**: 버디 ○ 파랑 테두리, 이글 ◎, 파 숫자만, 보기 □ 주황 테두리, 더블 ■ #F2683C 채움(흰 글자), 트리플+ ■ #D8323C 채움. (모양+색 둘 다)
9. **18홀 결과 띠**: 홀마다 작은 사각형, 위 색 규칙(파=--line2 계열 회색).

## 5. 새로 계산하는 분석 (기존 데이터만 사용, 18홀 라운드 기준)

| 항목 | 계산 |
|---|---|
| 그린 적중(GIR) 자동 | (타수 − 퍼팅) ≤ (파 − 2). 타수는 벌타 포함 |
| 파 유형별 오버파 | 라운드별 Σ(타수−파)를 파3/4/5로 나눠 평균. 홀당 = 합 ÷ 해당 홀 수 |
| 기간 변화량 | 구간 평균 − 직전 같은 길이 구간 평균 (데이터 부족하면 "—") |
| 흐름(누적 파 대비) | 홀 순서대로 Σ(타수−파). 고스트 라운드도 같은 방식 |
| 가장 크게 잃은 홀 | (타수−파) 큰 순 3개, 동점은 홀 순서. 원인 문장 = 티샷 결과·벌타·퍼팅에서 조합 |
| 티샷 방향 | 파4·5 홀의 좌/적중/우 개수와 비율 |
| 구질 분포 | 7종 개수, 좌타 방향 순서 |
| 바운스백 | (타수−파)≥1 인 홀 다음 홀이 ≤0 인 비율 (18번 제외) |
| 후반 체력 | 평균(후반 9홀 합) − 평균(전반 9홀 합) |
| 기복 | 18홀 총타의 표준편차(±) |
| 홀 난이도 히트맵 | 골프장·코스·홀별 평균(타수−파). 색: ≤0.6 회색, ≤1.0 연주황, ≤1.5 주황, 그 이상 진주황 |
| 다음 미션 추천 | 이번 라운드 손실 상위 항목 → 기존 미션 목록에서 매칭 3개 |

배지는 지금처럼 저장하지 않고 매번 계산.

## 6. 진행 순서 (단계마다 커밋, 스크린샷 확인)

0. **준비**: 현재 `index.html` 구조 파악. Playwright로 390×844 라이트/다크 스크린샷 찍는 스크립트(`tools/shot.mjs` 등, 배포엔 미포함) 작성 → 현재 화면 기준 사진 저장. 체험용 예시 라운드로 데이터 채워서 찍기.
1. 토큰·글꼴·공통 컴포넌트(3장) + 떠 있는 탭 바.
2. 홀 기록(입력) 화면. **입력 흐름 회귀 테스트**: 기본값 홀 "다음 홀" 1번, 벌타·스코어 연동, 9홀/18홀, 마지막 홀 완료 화면.
3. 홈.
4. 라운드 기록 4탭 + 공유 이미지.
5. 분석 화면 + 새 계산(5장). 값은 예시 데이터로 손계산과 대조.
6. 시작 화면 + 이미지 추가 + 서비스워커 캐시 목록/버전 갱신.
7. 코스·배지·더보기·새 라운드 스타일 정리, 다크 모드 전 화면 점검, 375/390/430 폭 점검.
8. 앱 버전 v64로 올리고 변경 요약 작성.

각 단계 끝에 **시안 파일과 내 스크린샷을 나란히 비교**해서 여백·크기·색이 맞는지 직접 확인하고 다듬은 뒤 다음 단계로 간다.
